# 现有程序逻辑说明

梳理日期：2026-10-22。依据当前项目源码、启动脚本与 README 整理；本文描述已实现的逻辑，不表示本次已经重新跑完数据处理。

后续实现已补充全文检索、无扩展名识别、Word/RAR读取、多项目候选、阶段材料和补建候选成果、附件矢量整理及人工图形判读。以下早期分节中的限制请以 README 开头和《需求对照检查.md》的“本轮代码落实”为准。目录标准及项目类型标准按用户回复暂缺，DWG仅整理原件，外部系统导入未执行。

## 1. 项目目前能做什么

围绕目标 Excel 中的项目，从台账、档案扫描件、PDF 和空间图层中查找证据，完成跨阶段挂接、字段候选整理、人工核对与 Excel 回填，并保留来源和验证记录。

已有两种使用方式：

| 方式 | 入口 | 用途 |
| --- | --- | --- |
| 批量流水线 | `run.ps1` | 按顺序执行检索、识别、挂接、补丁生成、Excel 导出和验证 |
| 本地可视化工作台 | `start-tool.ps1` → `app/server.py` | 上传工作簿、查看进度、核对候选、保存选择、下载成果 |

工作台默认地址为 `http://127.0.0.1:8766`，服务仅监听本机。

## 2. 已有的业务处理逻辑

### 2.1 数据源盘点与格式识别

程序：`scripts/inspect_sources.py`

- 遍历数据源目录，记录文件路径和大小。
- 读取 DBF 字段和属性记录，处理 UTF-8、GB18030 编码。
- 建立土地供应 ZIP 的文件目录索引，处理中文文件名。
- 按文件内容识别扩展名为 `.csv`、实际为 XLSX 的台账，转存为中间 JSON。
- 当前 DBF 盘点跳过路径中含“房屋”的文件。

### 2.2 目标项目材料提取

程序：`scripts/extract_materials.py`、`scripts/extract_pdfs.py`

- 根据目标表 B 列档案编号，在划拨 ZIP 中查找图片和 PDF；命中的文件进入提取列表；同号的多行保留为检索线索，页内归属另行核验。
- 只提取命中的材料，不解压整个档案包。
- 输出文件名加入路径哈希，降低重名覆盖风险。
- 图片转为 RGB，缩略至最长边不超过 2500 像素。
- 根据 28 位不动产单元号查找首次登记材料，仅纳入规划红线、选址、规划条件、划拨用地决定书等指定业务目录中的 PDF、JPG、PNG。
- 提取 PDF 各页文本，单独记录提取错误，并建立 OCR 清单。

### 2.3 PDF 页面渲染和本机 OCR

程序：`scripts/render_pdfs.mjs`、`scripts/ocr_images.ps1`

- 将目标 PDF 的全部页面渲染为图片，追加到 OCR 清单。
- 已有渲染图片默认复用；渲染脚本支持 `--force` 重新生成。
- 使用 Windows 本机 OCR 识别，已有文字文件直接复用。
- 识别失败记录 `.error` 文件；存在失败页面时，OCR 脚本报错，主流程停止。
- 批处理入口支持 `-SkipOcr`，用于已有 OCR 结果的情况。

### 2.4 OCR 字段候选提取

程序：`scripts/extract_fields.py`

通过正则提取以下候选：项目代码、电子监管号、合同号、不动产单元号、规划证号、批复文号、日期及带单位的用地面积原文。

同时检查页内文字是否包含目标项目名称，记录页内项目候选。正则命中不直接回填，输出仍标为 `NEEDS_LLM`，需要核实字段位置和本页所属项目，尤其是包含多条道路的合订本。

### 2.5 精确标识和模糊候选匹配

程序：`scripts/match_engine.py`

- 统一全角半角、大小写、空白和部分标点；“无”“待补”等占位内容按空标识处理。
- 支持平方米、亩、公顷、万平方米等面积单位换算。
- 对项目代码、监管号、合同号、单元号、文号、档案编号进行精确匹配。
- 有标识相同但其他非空标识冲突时，不作为无冲突精确匹配。
- 多个候选共享项目代码时保留一对多关系；可以用更具体的宗地标识进一步消歧。
- 名称、地址和面积用于候选排序，权重分别为 55%、25%、20%；模糊结果不自动通过。

### 2.6 空间相交与覆盖率计算

程序：`scripts/spatial_matches.py`

- 读取供地、报批和首登宗地图层，修复可处理的无效几何。
- 要求三个图层的 PRJ 文本一致，否则停止计算；没有自动坐标转换。
- 按监管号或合同号定位供地图斑，合并项目命中的供地范围。
- 计算与报批、首登宗地的实际相交面积、供地覆盖率、目标图斑覆盖率。
- 忽略小于 `max(1 平方米, 供地面积的 0.1%)` 的交集，结果按交集面积排序。

空间相交面积用于提供挂接证据，不直接充当法定审批面积。

### 2.7 多阶段挂接与附件指纹

程序：`scripts/link_stages.py`

- 对土地供应、土地首登、用地规划台账、工程规划台账分别运行匹配规则。
- 台账使用原始项目名称和项目代码的对应关系，发现人工补充名称与原始名称不一致时记录冲突。
- 空间候选唯一且双向覆盖率均达到 98% 时，标为 `MATCH_SPATIAL`。
- 供地图斑面积与目标表供地面积差异超过 2% 时，记录面积冲突。
- 计算 PDF 的 SHA-256，与用地规划、工程规划目录内 PDF 比较；同字节附件唯一关联时标为 `MATCH_ATTACHMENT`，共用材料转为歧义。
- 按文件大小和修改时间复用附件哈希缓存。
- 将缺解析器、OCR 不足、模糊匹配、歧义、冲突和未找到证据等情况输出为待复核队列。

### 2.8 自动补丁与已有值冲突处理

程序：`scripts/build_patches.py`

- 自动补丁只面向有证据的空白单元格；已有非空值与候选不同，记录冲突并保留原值。
- 同一单元格收到不同补丁候选时，阻止该格自动回填。
- 依据原始台账的精确项目名称及唯一项目代码，补充项目代码、建设单位等字段。
- 根据强空间证据补充报批批复文号、日期；要求唯一文号组累计覆盖至少 98%，其他文号组覆盖均不足 1%，并检查供地面积差异。
- 接收 `reviewed_fields.json` 中已核验字段，保留证据图片和来源。
- 输出回填溯源、已有值冲突、剩余空值及填充统计。

注意：这里按文号分组的回填规则，与上一节双向覆盖率的空间挂接状态规则不同。

### 2.9 人工复核、候选合并与选择保存

程序：`scripts/review_service.py`、`app/static/app.js`

- 汇总自动补丁、成果总表、规划台账、已有值冲突和空间候选。
- 从固定成果总表 `project_info_all_v5_a - 成果20261021.xlsx` 逐字段查找候选；唯一且无标识冲突的精确匹配可作为自动证据。
- 同一字段的等价候选合并，保留多个来源；相同来源和定位去重。
- 空白字段只有一个自动候选时自动补全；弱候选等待确认；多个不同候选或与原值不一致时标记冲突。
- 用户可以采用候选、确认保留原值或撤销选择，操作保存到任务文件。
- 按业务阶段、项目名称、档案编号和状态筛选，查看单元格原值、候选、来源文件及位置。
- 自动补全为绿色，冲突和待确认候选为橙色，人工采用或确认保留为蓝色。

工作台展示的业务分组包括项目信息、预审与选址、规划条件与红线、用地报批、土地供应；并提供 X:BQ 全部业务字段视图。分组存在不代表每个字段都已具备自动提取规则。

### 2.10 Excel 导出、原包保留和逐格验证

程序：`scripts/fill_workbook.mjs`、`scripts/preserve_original_package.py`、`scripts/verify_result.py`

- 用表格库导入工作簿，写入声明的补丁并导出。
- 默认拒绝覆盖原值；工作台中用户明确采用候选时允许对应单元格覆盖。
- 将补丁单元格放回原 XLSX 包，保留原包的其他内容，并增加必要的标色和日期格式。
- 逐格核对改动是否在补丁范围内、补丁是否落地，以及原值、公式、字体、边框、对齐、保护、批注等是否按规则保留。
- 检查工作表、合并单元格、范围、冻结窗格、筛选、数据验证、行高列宽和隐藏状态。
- 输出 `验证结果.json`；验证失败不会当作成功成果。

## 3. 两条完整处理流程

批量流水线：

```text
匹配规则测试 → 数据源盘点 → 图片提取 → PDF 提取 → PDF 页面渲染
→ OCR → 空间计算 → 字段候选提取 → 多阶段挂接
→ 生成补丁 → Excel 导出 → 原 XLSX 包保留 → 逐格验证
```

工作台流程：

```text
上传 Excel / 使用当前项目 → 模板校验 → 建立独立任务
→ 依次检索和处理 → 汇总字段候选与来源
→ 用户核对、采用或保留 → 导出 → 原包保留 → 逐格验证 → 下载
```

工作台检索阶段结束后不会立即导出 Excel，需点击导出；成果总表逐字段候选汇总属于工作台流程。`run.ps1` 不调用这一候选汇总逻辑，也不运行 `test_review_service.py`。

## 4. 工作台的任务与输入控制

程序：`app/server.py`、`scripts/review_service.py`

- 每次任务写入 `work/jobs/<任务编号>/`，原上传文件和输出分开保存。
- 检索任务串行执行，图片、PDF 和 OCR 资产缓存可复用。
- 支持任务状态、进度、运行日志和最近任务查询。
- 上传文件最大 25 MB；XLSX 解压总大小最大 100 MB，包内条目最多 2000 个。
- 首表须为 `Sheet1`，第 2 行须匹配当前 69 列模板，第 3 行起为项目，B 列档案编号允许重复，检索、核对和导出按表格行定位。
- 单表最多 5000 行，即第 3 行起最多 4998 行项目数据。
- 来源文件查看限定在项目目录或固定数据源目录内。
- 导出可以下载 Excel、用户选择与来源记录、完整日志和待复核队列。

## 7. 当前限制和未实现部分

- 数据源路径、部分图层名称、台账列位、成果总表文件名仍绑定当前赣江一张图项目，并非通用配置化工具。
- 默认输入是根目录 `test_result.xlsx`；README 记录当前样本为 11 个项目。工作台可以接收同模板上传文件，但模板容量上限不等于已验证该规模的处理性能。
- 不会把来源总表中额外的项目自动追加到目标表。
- 旧 XLS、旧 Word、DWG、RAR 尚未解析；识别到部分这类文件时记录待补解析器任务。
- 已有视觉识别任务队列和人工核验数据接口，没有自动调用外部大模型的实现。
- OCR 正则候选不会直接自动变成已核验回填值；仍需核实项目归属和字段含义。
- 模糊匹配只提供候选排序，空间交集不直接替代审批面积，多批次和共用材料仍可能需要人工消歧。
- 缓存主要依靠已存在的资产文件复用；本次未验证源材料更新后的缓存刷新行为。
- 源文件和 ZIP 按读取方式使用，成果另存副本；没有证据的字段保留空白。

本文仅完成源码层面的逻辑盘点，未重新执行 OCR、空间计算、全流程或测试；不据此认定现有输出全部有效。

## 8. 改造前核对：跨阶段材料互补的缺口

补充核对日期：2026-10-22。跨阶段互补已有部分实现，尚未形成“跨阶段找材料 → 识别材料业务类型 → 确认本页项目 → 提取目标阶段字段 → 合并候选 → 回填”的完整链路。

### 已经实现

- 从供应档案和指定首登目录中读取部分其他阶段业务材料。
- 利用台账、空间图层和相同 PDF 指纹进行跨阶段关联。
- 工作台可以汇总成果总表、台账和空间候选，并保留多个来源。

### 尚未打通

1. **检索覆盖不足**：主要提取划拨 ZIP 和指定首登目录；用地规划、工程规划目录中的 PDF 目前主要参与哈希比较，没有普遍进入目标项目的文本提取、页面渲染和 OCR 队列；出让材料也没有与划拨材料对等的提取链路。
2. **OCR 候选没有接到字段复核**：`extract_fields.py` 输出 `识别字段候选.jsonl`，但 `build_patches.py` 和 `review_service.py` 均未读取这个文件。正则识别到的字段通常停留在候选文件或待复核任务中，没有作为可选择的单元格候选展示。
3. **附件关联没有触发补充读取**：`link_stages.py` 记录附件哈希命中，但后续没有据此继续读取命中目录中的其他业务材料。
4. **缺少分轮扩展**：本轮新发现的项目代码、合同号、监管号、单元号没有形成统一的已确认标识集合，再用于下一轮跨阶段查找。
5. **材料类型与字段映射不足**：能识别编号和面积原文，不等于能区分预审拟用地面积、报批面积、供地面积以及对应日期。现有规则没有覆盖各类成果文件的完整字段解析。

### 现存输出提供的证据

- 根目录批量结果记录：11 个项目，新增回填 8 格，剩余业务空白 255 格；这不是 OCR 准确率指标。
- 根目录 OCR 清单共 630 页，其中供应阶段来源 618 页、首登来源 12 页，没有来自用地规划和工程规划目录的页面。
- `识别字段候选.jsonl` 共 630 条，其中 189 页有正则字段命中；命中率不等于字段正确率或回填率。
- 两个现存工作台任务各有 506 个业务单元格、270 格带候选；候选方法中成果总表精确编号匹配出现 243 次，不能把这些候选计作附件 OCR 的新增识别成果。

### 补齐顺序

1. 将已确认关联项目在供应、首登、用地规划、工程规划等目录中的相关业务材料纳入同一识别清单，分别保留存放阶段与材料所属阶段。
2. 将 OCR/文本字段接入工作台的单元格候选，并保留页码、原文、项目归属依据；归属不确定的放入待关联清单。
3. 使用已确认的新标识再次检索，补齐此前因缺代码或单元号遗漏的材料；有冲突的标识不扩散。
4. 按字段统计材料找到率、可读率、有效候选率及确认回填率，再逐类改进解析，避免用一个“识别率”混合衡量不同问题。

应允许从其他阶段保存的同项目原始业务材料补值，但不能直接把后续阶段的同名字段当作前序阶段事实。例如首登目录中的选址意见书可以补选址字段，首登面积不能直接替代选址面积。

## 9. 本次代码改造：供应优先的跨阶段互补

本节描述改造后的实现；上一节保留改造前的问题和基线统计，便于比较。

- **供应优先检索**：使用目标表的供应档案编号、监管号、合同号和无冲突供应图层名称作为起点。读取划拨、出让 ZIP，以及其他阶段目录和 ZIP 中命中的 PDF/图片。道路名出现在四至、邻接、路口描述中也保留为文件检索线索；项目名称、供应名称和位置支持模糊检索，命中后继续核验正文归属。
- **扩大关联目录**：原始台账名称对应的唯一代码、无冲突页内新编号、唯一同字节 PDF 关联可用于继续检索。双向覆盖均达到 98% 的唯一宗地，在供地面积核对通过后也可提供首登检索线索。所有这些新增目录关联均不直接授权回填。
- **分轮补充**：`expand_materials.py` 将新材料继续交给 PDF 渲染、OCR 和字段提取，最多扩展三轮。是否收敛、每轮新增数量和是否跳过 OCR 写入统计。
- **页内归属**：按项目名称或已有宗地层级标识确认唯一目标，冲突和多项目页面保留为未关联。供应简称只有在项目名称标签后出现才能参与页内归属；项目代码单独命中仍不足以确认具体宗地。
- **候选接入**：`extract_fields.py` 同时使用 PDF 原生文字和 OCR。`review_service.py` 将已确定页内项目的识别字段加入工作台单元格候选，保留存放阶段、材料业务阶段、页码、识别方式和原文；新增识别候选一律要求人工确认。
- **归属不明也保留可见线索**：只有一个供应关联项目、且没有相反标识或多项目证据的页面，可展示为“项目归属待确认”候选。用户必须在原件核对后主动勾选数值所属项目，后端校验确认记录后才允许采用和导出；未确认的项目标识不会进入扩展检索。
- **阶段字段分开**：按正文前部文书标题和明确标签提取字段，选址、规划条件、报批、供应的面积、单位、日期和编号分别映射。部分带清楚分隔符的地点、用途、依据、建设单位等文字字段也可进入候选。未识别版式不猜填。
- **失败可追踪**：单份 PDF 原生文字提取独立运行，最多 45 秒；失败记录在 `pdf_errors.json`，不阻止该文件之后尝试渲染/OCR。原生文字按文件大小与修改时间缓存。
- **渲染隔离**：单份 PDF 在独立进程渲染，最多 90 秒；坏文件或超时文件保留已完成页面并进入待复核队列。任务内复用渲染记录，源文件版本变化后刷新图片及对应 OCR 缓存。
- **两个入口均已接入**：批量 `run.ps1` 和工作台后台任务都会运行跨阶段扩展。批量模式输出待复核候选，自动补丁继续沿用已核实规则；工作台支持逐格采用这些新候选。

新增代码为 `material_evidence.py`、`cross_stage_materials.py`、`expand_materials.py` 和 `test_cross_stage.py`。新增产物包括 `材料识别统计.json`、`跨阶段检索统计.json`、`未关联材料.jsonl` 和任务内 `work/cross_stage_links.json`。

仍有边界：没有更换 Windows OCR 引擎，没有引入外部视觉模型；旧 XLS/Word、DWG、RAR、嵌套压缩包尚未增加解析器。跨阶段检索数量、字段候选数量与人工确认后的正确回填率分开衡量。
