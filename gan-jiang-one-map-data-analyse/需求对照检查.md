# 需求与实现对照检查

## 本轮代码落实（以下历史核对不再代表当前全部状态）

- `cross_stage_materials.py` / `extract_pdfs.py`：取消路径命中门槛，按文件头发现无扩展名图片/PDF；处理普通文件、ZIP/RAR 和已解压嵌套包；复用正文/OCR缓存。Word、旧Excel接入LibreOffice转换。错误包单独列出，不冒充空目录。
- `extract_fields.py` / `review_service.py` / `app.js`：正文名称、位置和面积匹配；多个项目候选逐行进入工作台，显示评分、来源及原文，采用前确认归属。
- `spatial_matches.py` / `spatial.js`：没有精确供地标识时展示独立的模糊图斑候选；缺当前阶段图斑时以虚线标明供应阶段参考范围；原件和图斑可对照判读并保存依据，不自动改字段。
- `governance_outputs.py`：选址意见书信息表、按阶段/文书编号整理的材料副本、供应目录建项清单、2017年后供应等文书补建候选、首登图层补建候选、监管号—单元号映射、项目类型待核定表和成果ZIP。补建依据单独记录，不修改原表；并非把候选当成已审批入库项目。
- `vector_outputs.py`：普通附件和包内SHP及组成文件整理、名称/标识候选、缺图项目和监管号补齐候选。新任务、批处理和下载入口均已接入。
- 另外修正：没有档案编号但有名称或宗地标识的行仍处理；缺可选成果总表不阻断材料核对。

实际验证：69项回归测试；12页已有真实OCR材料的整理、选址表和成果ZIP；实际三类图层空间匹配；本机Word转换、RAR成员读取与下载入口。真实材料另发现235张无扩展名JPEG及一份实际内容为HTML的RAR，前者现可进入识别，后者报告格式错误。验证目录为 `outputs/实现验证_20261022/`，不代表已重跑全量OCR或验收全部字段准确率。

按用户回复，暂不实现未提供的目录组织标准与项目类型新标准；当前采用阶段/文书编号整理并保留待核定状态。仍未实现DWG实体自动解析、栅格图件地理配准或向外部业务系统实际导入；当前人工判读为原件与图斑对照及结论留痕。

## 历史差距核对

核对日期：2026-10-22。依据：用户提供的《数据治理讨论 2026.10.md》及当前脚本、工作台实现。本次为静态实现核对及回归测试，没有重新扫描全部材料，不以已有输出推断业务要求已经完成。

## 本次纠正

- 档案编号唯一性并非需求要求。上一轮已取消；内部按目标表行定位，保留原档案编号和同号多行。
- “阶段间挂接方法”明确要求项目名称、地址、坐落等属性模糊匹配。原实现仅将模糊比较用于记录排序，文件检索仍主要依赖路径精确包含，覆盖不足。
- 原检索代码排除“某路以东/西侧/路口”等描述，这是擅自收窄检索。已删除此排除规则，四至和邻接描述命中的所有项目均进入检索候选。
- 项目名称、位置及中文供应名称线索现支持路径模糊检索，包括普通目录和 ZIP 内路径。短于四个字符的名称只做包含匹配；其余按局部字符相似度 80% 纳入候选。此阈值是尚未用业务标注样本校准的工程值。
- 模糊命中可以对应多行，不直接授权回填。文件正文识别、字段归属核验和人工确认继续执行。

## 检索与结果展示仍需补齐的问题

1. 路径无已知线索的文书需要先按业务材料类型发现，再依正文名称、位置、面积和编号匹配；目前仍可能漏检。
2. 多项目及模糊归属页面虽保存在识别与未关联清单中，但工作台单元格候选接入主要面向唯一归属或唯一待确认项目，多候选消歧展示还不完整。
3. 缺少逐份材料的检索命中原因、名称相似度及与多行项目对应关系的统一展示。
4. 55% 名称、25% 地址、20% 面积权重及 98% 空间强关联阈值是现有工程规则，不是需求文档给出的验收标准；不应据此删除低分材料或认定业务关系不存在。
