# OneMap 第一阶段 M1 + M2 联合关联验收

日期：2026-10-26。开发分支：`codex/m1-project-code`。范围仅为第一阶段 M1/M2，未开发 M3/M4/M5、第二阶段业务数据关联或第三阶段成果表。

## 实现流程

1. 复用七阶段扫描、散落文书归档、增量解压与校验及项目目录仓储。目录缓存绑定数据源；年份、格式、汇编容器不能作为项目根。复用原有解压文件时优先沿用实体目录已存边界，避免包装路径重复登记。
2. M2 先按完整 SHA-256 相等生成任意跨阶段目录候选，包含全部21组组合，保留双方材料逻辑路径、实体路径、材料 ID 和哈希。通用模板及一对多、多对多仅为候选。
3. M1 遍历所有有效项目大目录，包含 M2 已覆盖目录。从目录、文件名、PDF、DOCX、XLSX/XLSM、结构化记录取完整代码；局部归属不明、引用及多项目材料保留原文复核。代码一致不意味着宗地一致。无标签孤立代码不擅自确定归属。
4. 用稳定目录对 ID 合并 M1/M2 候选；M1 补齐 M2 未发现的目录对，并逐对校验已有 M2：可靠代码相同、冲突、单方缺码、双方缺码、归属未明分别记录。M2 原证据及方法签名不覆盖。
5. `methods` 保存命中方法，`evidence_type` 保存 M1/M2/M1+M2/conflict；审核状态仍独立为待确认、已确认、已排除、需复核。代码冲突进入复核，不自动确认任何关系。项目视图中未确认目录独立成行，逐条人工确认才参与组合视图。
6. 保存关系证据版本、方法签名、人工决定及历史、边界修改前后记录；新增证据及审核上下文变化使旧确认转为需复核。未关联是独立标记，带有待审核证据的目录也能按方法、阶段对筛出。
