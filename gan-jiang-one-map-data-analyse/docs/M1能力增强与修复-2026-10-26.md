## 已完成

- 复用七阶段扫描、项目目录仓储、压缩包解压和 M1/M2 审核流程；M1 独立运行不新增附件哈希。
- 项目代码共享完整格式验证；支持不同字段标签、相邻行及无标签完整代码。保留原始字形，不纠正 O/I/L 等疑似数字，排除明确的其他业务编号。
- A/B/C 证据分级。PDF 页面、DOCX 段落及表格行、Excel 单元格及行、CSV 行、JSON 记录保留独立出处和局部名称。无可靠上下文的 C 级证据不生成目录关系。
- 多项目、多代码及引用材料判定归属。同一记录两个代码不能因同一项目名称被提升；外部项目、无法归属记录保存为 unresolved_ownership。局部名称完全相等只用来核验归属，跨阶段仍只比较完整代码。
- OCR 默认关闭。开启后按候选页调用已有 PDF 渲染器及 Windows OCR；支持资源限额、有限重试、增量缓存及逐页断点继续。缓存命中不占新增文件/页额度，避免反复只处理首页。记录 failed/skipped/unprocessed/unrecognized，不把未处理当无代码。
- 可选模型命令适配器。片段最小化、严格 Schema、原文及代码二次核验、uncertain、调用次数/超时/费用上界和缓存。模型不配置时规则及 OCR 可用；模型不能自动确认、补码、修改目录或合并宗地。
- 保留同码一对多及多对多的独立候选。仅人工确认的目录关系参与已确认视图；任何归属证据、处理状态、目录边界或目录身份变化都会使旧确认失效。M2 方法证据和签名保留。
- UI 增加全部代码证据入口，包含没有候选关系的孤立/未归属代码；展示来源、原始及标准化代码、等级、位置、OCR/模型、冲突，支持状态分页及物理文件/PDF页预览。同码多目录提示不同宗地风险。
- Skill 同步真实编排、配置、支持格式、缓存升级和操作限制。

- M1 规则升级为 `M1-project-code-v3-ownership`。旧 `project_code_cache` 因源/解析版本不同重建，`project_codes` 保留表结构并重建派生 payload。人工决定及原有 M2 数据不删除。
- 新增同库 `code_recognition_cache(id,payload)`，成功页/模型结果即时提交。OCR 键绑定源根目录、物理路径、源元数据版本、页码、实际 OCR DLL/语言版本及适配/渲染脚本与依赖版本；模型绑定源、版本、位置、片段、Schema、命令及部署版本。

## 已知边界

- 归属采取保守策略：局部名称不能与目录精确对应、同一记录多个代码、引用或混入其他项目时可能减少候选，但保留证据供复核。不会使用名称/地址相似度补造命中。
- OCR 需要启用配置及 Windows 语言包，不能保证所有历史扫描件正确识别；额度耗尽的材料仍待处理。持续失败应排障或调整额度后重跑。
- DOC/XLS、加密文档及未知图形格式未新增正文支持；已有读取错误与跳过统计继续保留。图片格式和多帧处理见 Skill。
- 模型接口已通过结构和原文防伪夹具验证，具体供应商适配器需部署方配置并实测；单次费用上界须由适配器输出/token限制及实际计费校准。
- 源版本沿用大小/mtime/ctime；刻意保留全部元数据的内容改写仍需清理派生缓存。未引入 M1 全量内容哈希。
- 本轮已从 Git 索引移除全部60个历史 __pycache__ 文件，保留磁盘缓存；测试产物写入被忽略的 work/，不提交。
