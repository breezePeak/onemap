# 第二阶段设计：字段识别、关联与填写

## 边界与字段契约

唯一模板为用户 `F:\项目数据\test.xlsx` 的原样副本 `templates/test.xlsx`。`template_fields()` 读取 Sheet1 第2行，校验 A～BQ 69个非空字段，并拒绝69列外的有效表头。模板存在大量空白格式列，不作为业务字段。分组 X～AC、AD～AL、AM～AT、AU～BC、BD～BQ 固定，第3行示例不创建项目。完整字段快照见 `stage2-field-model.json`；生产配置始终由模板生成。

日期字段包括 AJ、AR、AY、BA、BP；数值面积包括 AF、AN、AV、AW、BH、BI。AA 是项目类型，AB/AC 是特征码，AW 是征收面积、AY 是报批日期，不能按近似概念填投资额、批次名称或耕地面积。特征码没有编码规则时留空。文号、合同号、项目代码和宗地编号保持字符串。

## D1：项目与目录

只读第一阶段 SQLite 项目目录库，使用稳定目录 ID。已识别独立目录是检索单元，不从模板示例或同名推定项目数量。目录不直接变成“已核实的 X 列项目名称”。HTTP 初始化复用 `mount_result()` 校验后的 M1/M2 关系，另存 `directory_links`，保留 confirmed/pending/review/rejected，不把待确认关系提升为归属结论。

显式上传的真实业务表另存内容指纹命名的不可覆盖副本，保留 A～BQ 原值及来源表行号，不与目录项目按名称合并。原始数据与目标字段配置分开保存。

## D2：材料与版本

扫描 `source_config.STAGES` 的七阶段有效资料。普通目录和第一阶段原地解压目录统一检索；未展开压缩包明确报告，解包及完整性继续由第一阶段负责。支持 PDF、图片、DOCX、Office 转换、XLSX/伪 CSV、文本、DBF、SHP/CAD。复用已有 PDF 子进程解析、PDFJS 单页渲染、Windows OCR、图像预处理与 QGIS/LibreDWG 读取。

材料同时保存实际存放阶段、实际文件类型、SHA-256、页/行/对象位置和业务文书类型。SHP 指纹包括 SHP/SHX/DBF/PRJ/CPG，属性或坐标系更新也会使版本变化。空白/解析失败页保留错误，其他有效页继续处理；整件无文字、转换器缺失、坐标系不明分别记录，不编造数据。

## D3：提取与 Agent 语义候选

复用 `material_evidence.field_candidates/page_evidence` 和 `entity_evidence.entity_blocks`。按标题及正文识别 S1～S4 文书，不按存放阶段填表。表格逐行和重复项目名称分段保留实体边界；原文不支持可靠分段时不得自动批量分配。

规则无法理解跨页条款或标签和值的复杂排版时，当前 Agent 查看原件后调用 `propose`。程序校验真实原件指纹、真实业务记录、字段分组、数据类型和原文片段出现；不把“片段出现”冒充语义正确。候选保留理由和待审核状态。原件未变化时，语义候选及已采用结果在重扫后仍可复用；原件或规则版本变化时重新审核。

S7 台账以 XMMC 为业务项目名，XMDM 为项目代码、XDDW 为建设单位；同时存在的通用“项目名称”列保留为原始事项名称，避免混淆登记事项与业务项目。

## D4：关系与空间证据

- M1 使用完整代码，确认后的新代码可以参与后续检索，但不合并宗地。
- M2 复用第一阶段附件关联和业务标识；相同 SHA-256 不使共享文件中的全部值归属所有项目。
- M3 复用投影校验、坐标转换和真实交集，展示原图斑、参考范围、交集及双方覆盖率。仅使用有明确坐标系的几何；局部交集保留为候选。关联绑定参考图斑与来源的双方版本。
- M4 名称及位置模糊匹配只扩大候选集合。
- M5 查看原件、图斑或原有空间核对工具后填写人工判读依据，建立业务记录关系，字段仍逐项审核。

`relations(project,record)` 保留多对多引用，同一业务记录可被不同项目引用，但每个字段的采用独立核对。`attach` 不批量采用字段。

## D5：值解析、审核与预览

有效原值优先。缺失值只有在唯一不动产单元号精确匹配、无冲突、非 OCR 原生文字且满足提取规则时自动补齐；代码、合同号、监管号、同名、目录和空间相交均不能单独自动填写。其他来源保留候选，冲突保留原值，没有来源保持空白。

审核动作 adopt/exclude/keep/review/undo 持久化到 decisions/exclusions/history。采用要求明确确认项目及宗地归属；源文件更新或参考图斑更新使采用状态变为 stale，历史不删除。撤销恢复原值或待审核状态。

面积证据保留原始表达。BH 明确为平方米字段，供应数值统一转换成平方米时 BI/BJ 必须同步，原始单位仍在候选原文中；其余面积与相应单位列分别保存。日期在预览中写为 Excel 日期，文号保持文本，不推导无依据日期或类型码。

预览直接复用模板 OOXML 包，替换 Sheet1 数据行，保留两行表头、合并关系和其他工作表/包内容；删除示例行并按真实业务记录生成。只输出69列，不插入来源字段。审核来源单独保存 `preview-audit.json`。正式格式整理和批量成果输出继续留给第四阶段。

## 持久化表

| 表 | 内容 |
|---|---|
| meta | 数据源绑定、模板指纹、字段配置、目录同步版本 |
| projects / originals | 独立项目记录、原始字段值、原表来源和行号 |
| directory_links | 第一阶段关系及确认状态 |
| materials / records | 原件版本、页/行/对象、原文、存放/业务阶段 |
| candidates | 字段编码、原始片段、类型化值、方法、可靠性、规则版本 |
| relations | 项目与业务记录关系、关联依据及双方空间版本 |
| decisions / exclusions / history | 当前审核、候选排除、不可覆盖的动作历史 |
| tasks | 任务进度、材料/页错误、完成或中断状态 |

数据库使用 SQLite WAL 和事务。工作台数据管理和一键清理均保护 `work/stage2/`，避免将业务审核当作可丢弃缓存。
