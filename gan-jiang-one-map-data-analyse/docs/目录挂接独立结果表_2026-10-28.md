# 第二步目录挂接独立结果表

完成度：已实现并验证。界面第二步“目录关联”新增数据库表，用于保存挂接数据。

## 数据结构与保存流程

第二步专用表位于 `work/folder_mount_organized/project_catalog.sqlite`，表名为 `directory_mounts`，与第一步的 `projects` 目录表分开。每条直接关联以关系 ID 为主键，保存双方项目 ID、阶段、物理路径、M1/M2 方法、状态、证据版本、证据数量、完整关系 JSON、人工审核 JSON（含历史）、有效标识及更新时间。

仅整理后目录的 `organized=True` 新扫描成功时写入当前候选关系，入口为 `scripts/run_organized_mount.py`。原始目录扫描和页面读取旧 JSON 均不写入此表。禁止从旧库、旧结果或旧审核记录回填新表。首次新挂接前保持空表。后续新扫描未命中的此前新关系标为 `active=0`；再次命中时恢复。完整证据版本仍保存在对应库的 `relation_snapshots` 中。

页面现已接入新库：列表、未关联项目、筛选、冲突、项目代码证据和关系详情全部从 SQLite 读取。`directory_mount_state` 单行记录本轮目录清单、统计、规则及扫描时间，与关系同事务提交，用于展示无关系项目及版本判断。新表保存人工决定和完整审核历史，不读写旧 `decisions.json`。重扫保留证据版本和审核上下文未变的决定；发生变化时转为待复核。审核事务再次校验数据源、规则、关系有效性和签名，拒绝过期提交。

批量写入使用事务，数据源不一致或关系字段缺失时回滚。未改变内容的记录不更新时间。

当前有效数据查询：

```sql
SELECT id, left_stage, left_path, right_stage, right_path, methods, status
FROM directory_mounts WHERE active=1;
```

- `app/static/index.html`、`mount.js`：新结果说明及空库提示。
- `scripts/test_directory_mount_store.py`：入库、审核、失效、恢复、错误回滚和数据源隔离测试。
- `scripts/test_folder_mount.py`：旧 JSON 不污染页面、新关系详情及审核入库、重扫保留决定和证据变化复核、失败存库不覆盖既有结果。
- `docs/skills/onemap-stage-mount/SKILL.md` 与已安装技能：同步仅新关系入库约定及查询边界。
