# 原始资料整理归档

默认源为 `F:\项目数据\赣江一张图`，目标为 `F:\项目数据\赣江一张图_整理`；目标结构是 `阶段文件夹/项目文件夹/原有材料结构`。不移动、删除或重组源资料。可以参考绑定该源的 `work/folder_mount/project_catalog.sqlite`、已有决策和人工确认；规则缓存只是线索，不能称为 Agent 已研判，也不能忽略边界复核标记。保留已有人工确认；仅在项目归属存在实质疑点时提出人工审核，不擅自覆盖确认结果。

## 判断对象与证据

项目边界是该阶段中一个独立业务对象的材料集合：建设工程、用地报批单元或供地/登记宗地。先明确本阶段的对象类型；同一建设项目可能包含多个宗地或批次，同一宗地也可能涉及多个工程。不要仅凭同名、共同项目代码、相同附件或上下级目录关系就合并不同宗地和批次。

对候选目录，按以下顺序取证并记录相应路径：

1. 查看所属阶段、父级分类/批次、候选目录、全部直接子目录及直接文件，结合相邻目录判断其所处层级。对于 ZIP 等已有解压副本，核实实际物理路径与包裹层；原包和副本的关系不等于两个独立项目。
2. 查看各子目录代表性文件名，必要时读取相关文书内容，比较项目名称、完整项目代码、宗地/地籍编号、批次、文号及其在文书中的含义。先区分“当前办理对象”和文书中引用的其他项目，不将引用编号直接作为归属。
3. 优先依据彼此一致的项目/宗地及文书内容判断；目录名称、序号和目录库规则是辅助线索。编号、名称、文书间存在冲突时检查原件及上下文，不以某一字段或多数表决消除冲突。若材料无法读取、空目录或只有宽泛名称，记录证据缺口，不猜测。

`inspect-tree` 的 `child_dir_names` 最多展示 25 项，`inspect-node` 的子目录与文件样例也有数量限制；它们不是完整目录清单。必要时直接列出完整目录、深入子目录或打开原件。不要将未读到摘要视为内容不存在，也不要把扫描提取的代码当作已经确认的项目归属。

## 项目归属可信度与人工审核

第一阶段以单个业务阶段内的项目归属为目标：尽可能将属于同一项目的材料整理到同一个项目目录。逐项研判后，给每个候选项目目录记录“目录内材料属于同一项目”的估计概率（0%～100%）、关键支持及反证、证据路径和判断范围；这是基于现有证据的主观估计，不是经过统计校准的准确率。无法合理估计时标记“无法估计”并说明缺少的证据，不凭目录名或空缺问题列表编造概率。

依据实际文书、项目名称和编号及上下文综合判断。证据充分、归属清楚的项目直接整理，不因需要人工确认或存在相同文件而一律要求复核；低可信度、材料不可读、项目归属冲突、可能混入多个项目或无法确定归属的材料列入人工审核，说明具体疑点和建议核查的材料。概率仅帮助排序，不以固定阈值掩盖明确冲突，也不把高概率当作人工确认。已复核的项目不重复审核，除非新增证据或发现实质冲突；记录审核状态，不将盘点、样本检查或台账文件名等同于已完成逐项目复核。

相同文件、哈希和重复目录只用于识别副本、保留来源或验证复制完整性；仅在它们有助于解决具体项目归属疑点时才检查，不以相同附件单独认定项目相同，也不单独作为人工审核事项。跨阶段关联不属于本技能。

## 分类与边界

- **project**：有材料和上下级证据表明它对应一个独立工程、报批单元或宗地。项目名称不一定含“项目”，同一项目内不同材料可以分在多个子目录。
- **material**：上级项目确定，子目录内容是该项目的不同材料，如测量报告、划拨决定书、交地确认书、宗地图或示意图。`06.示意图`、`07.备案通知书` 等序号可以是材料顺序，不是独立项目编号；但材料名称本身也不是排除独立项目的充分证据。
- **collection / classification**：年度、业务类别、档案整理层或包含多个独立对象的汇编。查看各子目录及材料，确认分别属于不同对象后向下划分；不能因为有两个编号子目录就断定是多项目。报批阶段的批次如果本身是独立办理单元，可是项目；如果内部证据表明包含多个独立办理单元，应继续展开。对于供地/首次登记，关注独立宗地和地籍单元，不能仅按建设工程名称合并。
- **unresolved**：证据不足、来源无法读取、存在无法消解的冲突或边界仍不清楚。记录候选路径、相反证据、缺少的材料和拟复核事项；保留原路径，不强制确定归属。材料中存在多个独立对象而无法可靠拆分时，同样标记待复核。

例如：`2022-00018 国家级技能人才培养综合园区公共配套一期工程——育匠路` 下的报批示意图、测量报告、划拨决定书、交地确认书和面积表，如果内容共同指向该工程及对应宗地，应作为一个项目；相邻目录中出现不同宗地或不同办理单元的有效证据，则应分别判断，而不是按材料名称机械套用该例。

## 决策与复制

在 `F:\lin_shi_project\onemap\gan-jiang-one-map-data-analyse` 下，可用 `python -X utf8 scripts/project_catalog.py --source "源目录" --storage-dir "目录库" inspect-tree --stage S4 --path "阶段内相对路径" --max-depth 2` 查看目录树，再用同一前置参数执行 `inspect-node --stage S4 --path "阶段内相对路径" --read-files --max-files 5`。上述工具打开目录库时可能清理失效的非人工项目缓存；只做盘点时使用该目录库的隔离副本，勿把它称作纯只读操作。若无可用目录库，可直接查看文件系统和文书；不要假造数据库决策。

有充分证据且需要供复制脚本使用时，可按 `project_catalog.py apply-decisions` 的格式写入 `project`、`material`、`collection`、`classification` 或 `unresolved` 决策，填写阶段、真实相对路径、理由与可核验的证据路径；记录判断来源与是否待复核。另在项目台账或报告记录归属概率及其依据、审核状态和具体疑点；现有决策格式若不支持这些字段，不要假称已写入目录库。存库是修改目录库，保持人工确认和现有审核记录。项目/容器关系需分别表达；不要将普通规则推断包装成 Agent 决策。

决策文件可用 `{"decisions": [{"stage_id": "S4", "rel_path": "阶段内实际目录", "node_type": "project", "reason": "基于实际文书的具体判断依据", "evidence_paths": ["阶段内实际证据路径"], "needs_review": false}]}` 组织。只有替换为实际存在且核验过的路径和依据后，才以同一源和目录库执行 `project_catalog.py ... apply-decisions --file "决策文件.json"`；具体参数以脚本帮助为准。复核或不确定的判断应相应设置 `needs_review` 或 `unresolved`，并复查清单的实际归属。

```powershell
python -X utf8 scripts/organize_copy.py plan
python -X utf8 scripts/organize_copy.py copy
```

`plan` 复制并使用原始目录库，仍会对未命中目录调用规则推断；它不执行上述语义研判。检查 `work/整理项目索引.json` 与 `work/整理复制清单.jsonl`：核对实际项目边界、复核项目、未归属文件、同名冲突和来源，不仅看数量。若发现证据不足或误判已被规则当作项目，先纠正目录库或保留待归属，再重新生成清单并核对；现有复制工具没有按项目选择性排除功能，不能声称它会自动隔离全部存疑项目。无法安全处理时保留清单及问题，不执行受影响的复制。

`copy` 目标必须是已存在的空目录，不能覆盖现有成果；可用 `--source`、`--destination` 指定路径，但目录库必须绑定所选源。它逐文件检查源版本和 SHA-256，并保存索引与清单。失败会留下部分文件，不要直接对非空目标重跑或删除已有成果；工具不复制没有文件的空目录，原压缩包和已解压副本均按现状复制。报告每个项目的归属概率或无法估计的原因、判断依据、审核状态，以及仍需复核/待归属的范围及异常。整理完成后的跨阶段挂接使用 `onemap-stage-mount`。

工作台的“整理目录”步骤只读展示 `work/项目边界全量复核台账_*.json` 中最新台账的项目、问题、来源及证据路径，不会启动整理、更新台账或确认边界。更新台账后可在页面刷新；没有台账或台账过时应如实报告，不把页面显示当作项目验收。
