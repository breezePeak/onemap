# 整理目录项目挂接

默认输入 `F:\项目数据\赣江一张图_整理`，须包含七个阶段目录。挂接程序把各阶段的直接子目录作为项目边界，项目内部目录属于该项目；跳过阶段下的 `_待归属资料` 和阶段根目录散落文件。项目内压缩包作为现有文件处理，不解压或修改资料。

## 挂接前检查边界

读取 `整理项目索引.json`（如有），结合目录内容及来源检查项目边界，特别关注 `boundary_review`、规则来源、未经确认或已变化的目录。索引只反映整理时的记录，不证明当前目录完整或判断正确；无索引时直接检查目录结构与代表性材料，不虚构来源。

确认一个目录是项目时，检查其阶段业务对象、直属子目录及代表性文书：同一工程或同一宗地的测量报告、决定书、图件和交地材料通常属于同一项目；材料序号不自动构成独立项目。发现目录实为多项目容器、材料子目录、存在不同宗地/批次或名称、编号和内容冲突时，按 `onemap-archive` 的取证标准进一步核对。不能凭共同代码、同名或相同附件直接合并不同项目/宗地。证据不足、资料不可读或存在矛盾时保留路径、相反证据和复核原因。

程序不会根据语义检查自动拆分、修正或排除这些问题项目：如边界存在未解决的问题，先回到整理流程处理，或保留明确的复核记录并在交付中指出相关结果受影响；不要把候选关系说成确认关系，也不要声称问题目录已经自动过滤。已有 `boundary_review` 会从整理索引传入挂接库；对本次新发现的问题，不能仅依赖程序自动产生标记。

## 执行与交付

在 `F:\lin_shi_project\onemap\gan-jiang-one-map-data-analyse` 中执行：

```powershell
python -X utf8 scripts/run_organized_mount.py --methods M2
# 如需 M1 补充项目代码：--methods M1 M2
# 使用其他整理目录：--source "完整目录路径"
```

结果独立保存在 `work/folder_mount_organized/result.json` 和 `project_catalog.sqlite`，不覆盖原始目录的 `work/folder_mount/`、其人工审核和旧结果。M1/M2 只产生候选；审查来源、项目代码归属、共同附件、相同代码的多宗地/多对多、边界疑点及冲突后再人工确认，不由共享证据自动合并。报告异常、缺少材料、未归属和待复核项目。

第二步新挂接关系必须写入 `work/folder_mount_organized/project_catalog.sqlite` 的独立 `directory_mounts` 表。仅本次 `organized=True` 扫描成功产生的关系允许入库；禁止读取或复制 `work/folder_mount/result.json`、旧库关系、旧审核记录来回填新表，禁止通过页面读取触发导入。首次新扫描前保持空表，不为验证而导入历史关系或执行全量真实挂接。原始目录扫描不写此表。

表中保存双方目录、匹配方法、证据版本、状态、完整证据及审核信息。同库 `directory_mount_state` 保存本轮目录清单、扫描时间、规则版本及统计，与关系同事务提交。后续新扫描未命中的此前新关系标为 `active=0`；查询当前结果需加 `WHERE active=1`。`result.json` 仅保留为本轮扫描结果文件，不作为新表的数据导入来源。

工作台第二步“目录关联”的列表、筛选、冲突及代码证据、关系详情均读取上述独立数据库；人工确认、排除和复核直接更新新表及审核历史，不写旧 `decisions.json`。空库显示“暂无新挂接结果”；页面读取禁止回填旧数据。重扫时证据签名、审核上下文及规则版本未变则保留人工决定，发生变化则转为待复核。关系消失或签名过期时拒绝旧页面提交。

技能执行后应明确告知用户刷新目录关联页面查看新结果；字段提取业务库的目录同步尚未切换，不得声称已完成业务字段导入。原始数据整理使用 `onemap-archive`，不是本技能职责。
