## 本地可视化工具

工作台分为“项目文件夹挂载 / 提取项目数据 / 数据制表”三个模块，默认进入文件夹挂载。点击“扫描 / 更新关联”只盘点现有数据源与共享解压索引，按跨阶段非空文件的 SHA-256 相同建立文件夹候选，不启动 OCR、回填或新包解压；PRJ/CPG 是通用坐标系、编码说明，不作为关联依据。表格显示两端阶段、直接包含文件的目录、相同文件原路径和指纹，支持搜索、每页 50 条分页、待确认/已确认/已排除/未关联筛选以及逐对确认、排除、撤销。结果与确认记录保存在 `work/folder_mount/`，重启保留；重新扫描发现证据指纹集合变化时，关系恢复待确认。未解压且无索引的包内文件不参与；共用附件不能自动证明同一项目，确认关系不传递合并目录。第 2 模块保留原有检索界面，第 3 模块暂留入口，后续分阶段调整。

首版支持与当前文件相同的 69 列模板（第 2 行字段名、首表名 `Sheet1`、第 3 行起为项目、B 列档案编号允许重复，内部按表格行定位），单文件最大 25 MB、4998 个项目。其他模板会明确拒绝，不按错误列位回填。

每次上传任务单独保存在 `work/jobs/<任务编号>/`，不覆盖原文件。图片/PDF 与 OCR 文字保存在 `work/`。新任务和批处理会自动接回历史任务、跨阶段试跑中的成功 PDF 文字和渲染缓存，并核对源文件版本，避免重复解析和渲染；复用数量见 `cache_reuse.json`。项目归属和字段匹配按当前表格重算，用户选择保留在各自任务中。同一服务按顺序检索以避免缓存竞争。选中的值和每个来源文件/定位会写入该任务的 `用户选择与来源.json`，导出文件逐格验证。

后端为 Python 标准库 HTTP 服务，前端为本地 HTML/CSS/JS，无云端上传及额外前端依赖。`scripts/review_service.py` 管理字段候选、来源合并及选择，复用现有脚本检索和导出。

### 跨阶段材料互补（供应优先）

优先处理土地供应档案编号、监管号、合同号及供应名称命中的材料；没有路径线索的材料同样读取正文或 OCR。普通目录、ZIP/RAR 及已解压嵌套包均参与检索。四至、邻接、路口描述不再排除，名称和位置支持模糊检索；正文面积近似也能产生待确认候选。当前名称阈值 80%、面积误差阈值 2% 仅用于提供线索，尚未经业务标注校准。共享标识不作为目标行主键，多个项目候选分别展示。扩展检索最多三轮，达到上限仍有新增会在日志和统计中提示。

材料的存放阶段与正文识别出的业务阶段分开记录。例如首登或工程规划目录内的选址意见书，可以产生预审与选址字段候选。PDF 原生文字与本机 OCR 均参与提取，页内名称或已知供应标识须唯一命中且无冲突；多项目页面、归属不明及标识冲突不会仅按目录分配。

新增的跨阶段识别值在工作台中作为**待人工确认候选**，包含原文、页码、识别方式和来源，不直接自动回填。字段目前覆盖项目代码及带明确标题/标签的选址、规划条件、报批、供应文书编号、日期、面积和部分建设单位；未识别标题或版式的内容仍需人工核验。批量模式输出同一候选文件供复核，自动补丁继续采用原有已核实规则。

目录、正文名称、位置或面积线索可形成一个或多个“项目归属待确认”候选，工作台展示全部候选项目及评分。采用前必须查看原件并勾选确认该页数值属于当前项目，后端校验并保存确认记录。有相反标识的关系保留在未关联清单中；未经确认的编号不用于继续扩散检索。

新增结果：`材料识别统计.json`、`跨阶段检索统计.json`、`未关联材料.jsonl`；检索线索保存在任务 `work/cross_stage_links.json`。共享项目代码只用于扩大检索，不当作宗地唯一标识。没有新增外部识别服务。

单份 PDF 原生文字提取最多 45 秒、页面渲染最多 90 秒，失败会保留原件、已完成页和待复核记录，其他文件继续处理。渲染错误在 `work/pdf_render_errors.json`，并进入待复核队列。失败渲染记录在同一任务中复用；单独执行 `render_pdfs.mjs --force` 可重试。源 PDF 版本变化后会刷新对应图片与 OCR 文字缓存。

## 运行

在本项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

已完成 OCR 时可以传入 `-SkipOcr`。OCR 全部在本机执行，需要 Windows 中文识别语言包。读取 WinRT 图片被沙箱拦截时，需在普通本机 PowerShell 运行，不要把失败识别视为成功。阶段报错会停止流程。

程序优先使用 Codex 已配置的 Python/Node 运行库。表格通过 `@oai/artifact-tool` 导入、定点修改和导出；本项目的 `node_modules` 联接指向已有运行库。空间库已安装到 `work/python_packages`，其他 Python 依赖见 `requirements.txt`。迁移到其他机器时需要重新准备这些依赖和联接。

## 程序分工

| 程序 | 用途 |
| --- | --- |
| `inspect_sources.py` | 只读盘点文件、ZIP 目录和 DBF 属性，按文件内容识别伪 CSV 台账 |
| `extract_materials.py` | 按完整档案编号提取目标项目扫描件；文件名带路径哈希避免重名覆盖 |
| `extract_pdfs.py` / `render_pdfs.mjs` | 提取 PDF 文本，完整渲染扫描页；跳过首登身份和人证资料 |
| `ocr_images.ps1` | 本机中文 OCR，缓存逐页文字并保存识别失败原因 |
| `extract_fields.py` | 从 OCR 提取代码、监管号、合同号、单元号、文号、日期及面积候选 |
| `material_evidence.py` / `cross_stage_materials.py` | 页内项目归属、文书类型与字段映射；供应优先的跨阶段检索及附件关联 |
| `expand_materials.py` | 利用新线索分轮读取、渲染和识别更多材料 |
| `match_engine.py` | 精确标识、编号冲突、一对多、名称/地址/面积相似度规则 |
| `spatial_matches.py` | 校验坐标系，计算供地与报批/宗地实际交集及双向覆盖率 |
| `link_stages.py` | 运行多路挂接，比较同字节附件 SHA-256，打印日志并输出识别队列 |
| `build_patches.py` | 仅生成有证据的空白单元格补丁，已有值冲突单列 |
| `fill_workbook.mjs` / `preserve_original_package.py` / `verify_result.py` | 通过表格库生成补丁单元格，再放回原 XLSX 包以保留字体字符集等元数据；逐格验证值、格式、公式和相关设置 |
| `test_match_engine.py` | 空键、冲突编号、共用代码、面积单位、模糊结果不自动通过的测试 |
| `test_review_service.py` / `test_cross_stage.py` | 选择保存、冲突保护、跨阶段检索与识别候选接入测试 |

## 日志和人工/大模型接口

结果集中在 `outputs/governance/`：

- `挂接日志.log`：可直接阅读；控制台同步打印状态、项目、阶段、理由、候选和证据。
- `挂接明细.jsonl`：每行一个挂接事件，含相似度、面积误差、交集面积、覆盖率或附件指纹。
- `待复核队列.jsonl`：需要大模型、模糊匹配、消歧、冲突处理或补来源的任务。
- `识别字段候选.jsonl`：每页 OCR 字段候选，保留图片、来源和页内项目候选。
- `填充溯源.csv`：每个回填单元格的值、规则和证据。
- `已有值冲突.csv`：原值与来源不一致，原值保留。
- `剩余空值.csv`：业务区 X:BQ 的未填字段及原因；空白不自动当成零或不适用。
- `验证结果.json`：最终逐格验证结果。

| 状态 | 含义 / 下一步 |
| --- | --- |
| `MATCH_EXACT` | 编号无冲突且候选唯一；重复图斑不会被悄悄选第一条 |
| `MATCH_ATTACHMENT` | 同字节附件唯一关联；共用材料会转入消歧 |
| `MATCH_SPATIAL` | 唯一且双向高覆盖空间候选，不等于法律属性已经可直接复制 |
| `NEEDS_FUZZY` | 缺精确标识，查看名称/位置/面积或空间候选 |
| `NEEDS_LLM` | OCR 缺失、字段位置或页内项目归属需视觉核实 |
| `NEEDS_PARSER` | 缺 LibreOffice/bsdtar、伪扩展名 XLSX 或 CAD 实体待解析等情况，日志保留原路径 |
| `AMBIGUOUS` | 一对多、重复代码、共用附件或候选接近，禁止默认选第一条 |
| `CONFLICT` | 编号或台账列发生冲突，先查原始材料 |
| `NOT_FOUND` | 当前扫描来源未找到证据，不表示阶段不存在 |
| `REVIEWED_VISUAL` | 对应图片已核验，采用值见填充溯源 |

大模型队列中的 `image`、`ocr_text` 和 `source` 可直接交给视觉识别程序。先确认本页项目，再提取字段、单位和证据；不得按目录名称强行认定本页属于该项目。现有脚本不绑定外部大模型服务，也不上传材料。

核验后的值维护在 `reviewed_fields.json`，包含 `project`、列号 `column`、`value`、`source`、`evidence_image`。更新后依次执行 `build_patches.py`、`fill_workbook.mjs`、`preserve_original_package.py`、`verify_result.py` 即可回填。本次已有六项视觉核验结果。

## 当前边界

工作台主核对表保留上传项目。未关联且证据满足日期、名称和文书编号条件的供应等阶段项目，以及未关联的首登图层记录，写入独立的含补建候选表，附来源与待核实状态；冲突、多标识或同单元号多条记录另列待消歧，不改变上传原表。Word/旧 Excel 依赖本机 LibreOffice，RAR 依赖系统 bsdtar；损坏、伪扩展名或加密包明确报错。DWG 原件已整理但未自动解析实体。道路可能跨多个批次，整批面积不能复制为单宗地的审批面积。

所有模糊匹配目前只排序候选；空间相交面积只用于挂接证据，不当作法定审批面积。合订本可能包含多条道路，存在“同一项目代码对应多宗地”“同一合同多个图斑”，必须保留一对多关系。输入台账的人工补充名称与原始 XMMC 部分错位，禁止简单横向拼接。

源文件和源 ZIP 不修改、不删除；输出是单独副本。当前回填是经核实的首轮成果，剩余空白和识别任务未宣称完成。
