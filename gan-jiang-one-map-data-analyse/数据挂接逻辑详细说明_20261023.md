# 数据挂接逻辑详细说明

日期：2026-10-23。本文根据当前代码整理，说明已经接入的逻辑、具体判断条件及现有限制。它描述程序行为，不代表所有原始材料均已完成核验。

配套图示：[数据挂接流程图（10张）](F:/lin_shi_project/gan-jiang-one-map-data-analyse/数据挂接流程图_20261023.md)。

## 1. 挂接的对象和结果

系统从目标工作簿的一条项目记录出发，寻找对应的台账记录、业务文书、附件和空间图斑，再将有依据的字段作为回填候选。

必须区分三个结果：

1. **检索命中**：发现一个可能有关的文件或记录。目录名、档案编号、名称近似、地址近似、相同附件均可用于这一步。
2. **归属判断**：判断该记录、页面或页内实体是否属于当前项目。检查名称、业务编号、四至和跨项目冲突。
3. **字段采用**：判断具体字段能否自动填空，还是需要人工选择。即使项目归属明确，新识别的文书字段仍作为人工核对候选。

所以，“找到了文件”“编号一样”“有空间相交”都不直接等于“把整份文件的所有字段填进这一行”。

## 2. 档案编号与项目身份

### 2.1 档案编号不作唯一键

目标表从第 3 行读取项目，每条记录在当前任务中用 `row-行号` 标识，例如 `row-124`。档案编号可以重复，不因重复而拒绝上传，也不会仅按档案编号将两行合并。

档案编号的用途是辅助定位目录和扫描件。它没有进入通用精确匹配编号集合。一个档案可以关联多个项目候选，一个项目也可以关联多个档案和图斑。

行标识只对本次工作簿有效；重新上传并调整行顺序后，不能将它当作跨任务永久项目编号。

### 2.2 从目标行读取哪些依据

| 依据 | 当前来源及用途 |
| --- | --- |
| 档案编号 | 第 2 列；辅助检索，不作唯一约束 |
| 项目名称 | 优先第 24 列，再取第 10 列、第 3 列 |
| 项目代码 | 第 25 列；精确匹配依据，但可能覆盖多个宗地 |
| 电子监管号 | 第 18 列；供应及材料归属依据 |
| 合同号 | 第 19 列；供应及材料归属依据 |
| 不动产单元号 | 第 15 列，当前要求长度为 28 才作为该项身份依据 |
| 规划条件编号 | 第 43 列 |
| 批复文号 | 第 52 列；可能指向整批范围 |
| 选址证书文号 | 第 35 列 |
| 地址 | 优先第 59 列，再取第 12 列 |
| 面积 | 第 61 列数值和第 62 列单位，换算为平方米比较 |

人工已经采用的候选会参与后续目标身份重建。归属待确认的候选，必须同时有人工项目确认才会参与。

正文新识别出的编号，仅在“唯一归属一个项目、没有身份冲突、该编号只有一个不同值、目标原来没有值”的情况下作为推断编号补入检索身份，并标记为 `inferred_keys`。仅靠这种尚未确认的编号，不升级为自动精确采用。

## 3. 数据源与执行顺序

当前主流程依次执行：

1. 盘点原始文件、压缩包成员、图层和台账。
2. 优先读取供应扫描件。
3. 跨阶段读取 PDF、图片和可支持的办公材料，包括路径没有项目线索的材料。
4. 渲染 PDF 页面；读取原生文字和本机 OCR 结果。
5. 读取附件 SHP、DWG/DXF 和已配准图件，整理坐标与几何。
6. 计算参考图斑及空间关联。
7. 分析页内实体、项目归属及字段候选。
8. 利用新编号、别名、附件指纹再扩展检索，最多 3 轮。
9. 输出阶段挂接状态、冲突及待核对队列。
10. 建立可回填补丁、剩余空值和冲突清单。
11. 整理阶段材料、选址信息、补建项目等成果。
12. 合并成工作台中的逐单元格候选，供核对和导出。

扩展检索在“无新增来源且归属关系不再变化”时提前停止。达到 3 轮仍有变化时，会在统计中记录尚未收敛；当前不是无限迭代。

## 4. 文件是怎样被找到的

### 4.1 编号和目录检索

以目标中的业务编号、档案编号、名称、位置及人工别名建立检索词。英文数字编号匹配时检查字符边界，减少短编号嵌在长编号中造成的误命中。

供应图层中监管号或合同号一致且两项没有冲突的项目名称，可补成检索别名。原始台账中，名称完全一致且只对应一个项目代码时，也可补入检索词。已有明确空间对应的唯一首登宗地，可以补充单元号检索词。

这些补充扩大的是检索范围，不直接修改原始工作簿。

### 4.2 名称模糊检索

名称先做统一大小写、全半角和常见分隔符标准化。没有删除“工程”“一期”“提升”“整治”等业务描述词的通用规则。

路径和正文检索采用字符序列相似度：名称完整出现时记为 1；否则在文本中按接近名称长度的片段比较，达到 0.80 时可以扩大检索。短于 3 个字符的名称不作该模糊检索；3 个字符仅支持完整包含。

例如，“儒乐湖生态综合整治提升项目（一期）儒乐桥工程”与简称不必完全同名，也有机会成为候选。命中不代表已经确认两者为同一项目。

### 4.3 全文扫描

受支持的材料即使文件路径没有命中名称、编号或地址，也可进入全文扫描；有路径线索和业务关键词的材料排在前面。因此，不是仅靠文件名寻找文件。

### 4.4 相同附件指纹

用 SHA-256 判断附件是否字节完全相同。当前这条关联主要用于 PDF：若供应相关附件与规划目录中的 PDF 完全相同，可扩展所在项目代码目录的检索。

只有单一项目和单一项目代码目录的对应才能形成明确附件指纹挂接；共用附件、多个项目代码目录出现同一文件时保留歧义。该方法不支持“同一文书重新扫描后字节不同”的识别，也不是所有格式的内容相似检测。

### 4.5 当前仍存在的排除和格式限制

当前代码仍跳过 Office 的 `~$` 临时锁文件；跨阶段文件检索还会按路径中的“身份证、身份复印、授权、委托、营业执照、户口、人证、法人证明”排除部分材料。主数据图层目录不作为普通文书重复扫描，而走图层处理。

**这项路径排除确实仍在代码里，不能描述成“所有名称描述都不会排除”。它可能漏掉同时包含业务材料的混合文件。**名称模糊匹配与这项文件检索排除，是两套不同规则。

不支持、实际格式与扩展名不符或缺解析器的文件，会进入解析待办；当前不是每种文件均保证读取成功。

## 5. 结构化记录怎样比较

### 5.1 标准化

匹配时统一全半角、大小写并去除空白及常见标点。`无、暂无、待补、待核实、NULL、NONE、N/A、-、/` 等视为空值。它们不参与有效编号命中。

面积支持平方米、㎡、M2、亩、公顷、万平方米；亩乘以 `2000/3`，公顷及万平方米乘以 `10000`。未知单位、不合法数值或非正面积不作为有效面积。

### 5.2 精确标识和冲突

精确比较的七类业务标识为：项目代码、监管号、合同号、单元号、规划条件编号、批复文号、证书文号。

同一类编号两边都有有效值且相同，记为命中；两边都有值但不同，记为冲突。一项编号相同不能抵消另一项编号冲突，名称再接近也不抵消编号冲突。

判断顺序如下：

1. 只有一条无冲突的精确候选：有至少一项非推断编号命中，记为 `MATCH_EXACT`；命中全是推断编号则仍需确认。
2. 多条无冲突精确候选：若其中恰好一条命中监管号、合同号或单元号，可进一步选出该条；仍须检查该命中是否仅来自推断编号。
3. 其余多条精确候选：记为 `AMBIGUOUS`，不强行选择。
4. 没有无冲突精确候选，但存在编号命中又冲突的候选：记为 `CONFLICT`。
5. 没有候选：`NOT_FOUND`。
6. 其余进入模糊候选判断。

注意：以上是通用记录匹配规则。页面归属对“项目代码单独命中”更加保守；空间定位则允许同一项目的多条无冲突图斑组成参考范围，不能把所有模块理解成同一条一对一规则。

### 5.3 模糊候选评分

结构化记录只要满足下列任一项，就可进入候选池：有编号精确命中；名称相似度至少 0.45；地址相似度至少 0.65；面积相对误差不超过 2%。冲突仍会被标记，供后续阻断。

面积相对误差 = `|目标面积－候选面积| / max(目标面积, 候选面积)`。

综合分 = `0.55 × 名称相似度 + 0.25 × 地址相似度 + 0.20 × 面积得分`，其中面积得分为 `max(0, 1－相对误差)`；面积未知记 0。名称和地址别名可提高对应分项。

排序优先看“无冲突精确命中”，再看命中编号数量，再看综合分。没有精确命中时，前两名分差小于 0.08，标记为歧义；否则仍只是模糊候选，**不存在达到某个综合分就自动通过的规则**。通用模块通常保留前 5 条用于核对。

这些数值是当前程序规则，不是已经通过业务样本校准的准确率或置信概率。

## 6. 地址、四至和曾用名称

地址同时做字符相似比较和明确四至解析。

“甲路以东”和“西至甲路”都描述项目在甲路东侧，按同一约束处理；“甲路以东”和“甲路以西”产生相反方位冲突。相同道路的相反方位会把地址得分降为 0，并作为身份冲突，不能由名称相似度抵消。

人工可保存项目历史名称、地址别名和道路曾用名。道路别名按已确认的“曾用名→现名”替换后比较。当前主要支持明确的东南西北与道路、河湖等句式，不包含自动地址地理编码，也不保证识别所有自然语言四至。

## 7. 文件找到后，怎样判断页内项目归属

### 7.1 先区分页和实体

PDF 按页记录；同一页同时保留原生文字和 OCR 来源。出现重复“项目名称”标签时分段；明确的制表符表格按行分段；有 OCR 坐标且存在明确双栏项目标签时尝试左右分栏。

字段在所属实体段内提取。后一个项目可继承文书类型标题，但不会继承前一项目的编号。无法可靠分段时保留整页，不能声称已经完成任意复杂版式解析。

导出按“来源页面＋实体分段”归并；同一实体的原生文字/OCR 归属矛盾仍会合成冲突，不会当成两个独立可靠项目。

### 7.2 强归属条件

在该实体内，目标项目完整名称命中，或者已有监管号、合同号、单元号命中，可以形成强归属依据。同时检查七类业务编号冲突。

只有该实体中的名称、强归属项目和冲突集合最终唯一指向一个项目且没有冲突，才记录明确归属。**项目代码单独命中，即使目标表只出现一行，也不能单独确认页面归属**，因为它可能覆盖多个宗地。

供应图层补出的简称，仅在“项目名称/建设项目名称”标签之后按限定句式命中时用于强归属，避免地址里出现同一道路名就认成项目名。

### 7.3 待确认归属

目录检索线索、正文名称/地址相似度至少 0.80、面积误差不超过 2%、OCR 纠错提示等，可以产生待确认项目候选。仅有面积相近也可供核对，但不会直接确认归属。

页面出现与目标不一致的有效业务编号或相反四至时，不将该目标当成无冲突归属候选。没有明确归属的材料仍保留，输出到未关联材料清单。

### 7.4 OCR 编号纠错

当前仅针对已知目标编号，处理一个字符的形近误识别，例如 O/0、I/1、B/8 等。必须能唯一对应到一种编号和值；已识别出另一合法编号时不强行替换。

保留识别原文、建议值和修正原因。建议用于扩大核对范围，不作为无条件自动写入依据；多字符错误和任意未知编号修复尚未实现。

## 8. 怎样判断材料属于哪个业务阶段

材料的存放目录与材料业务阶段分别保存。放在供应档案里的选址意见书，仍按选址意见书提取字段，不把它当成供应面积来源。

当前主要检查正文前 300 个标准化字符中的标题，分类为：预审与选址、规划条件与红线、土地供应、用地报批。未识别到标题记为未分类，不从目录强行猜阶段。

| 材料阶段 | 主要字段候选 |
| --- | --- |
| 预审与选址 | 位置、用地面积、规模内容、建设依据、证书文号、发证日期、面积单位 |
| 规划条件与红线 | 地块编号、面积、性质、位置、条件编号、出具日期、出具依据、单位 |
| 用地报批 | 用途、批准面积、批复文号、批复日期、单位 |
| 土地供应 | 受让人、用途、位置、供地面积、方式、方案批复文号、权属来源、合同/决定书编号、日期、供地单位 |

项目代码可独立提取；其他字段结合业务标题与具体标签提取。日期必须是有效日期；没有可靠分隔符的整段 OCR 文本，不强行切成文本字段。未覆盖的字段不会因为表格有空白就推测补齐。

## 9. 空间挂接的完整过程

### 9.1 几何和坐标准备

读取供地、报批、首登三类主图层，以及附件 SHP、可读取的 DWG/DXF、配准图件边界候选。

面积计算采用以米为单位的投影坐标系，以供地图层为参考；其他坐标已知时转换后计算。附件须状态为 `READY` 且有正面积面几何才能参与。未知坐标、部分读取 CAD、只有点或无法形成有效面的线，不能当成已完成自动空间挂接的土地范围。

不能仅凭坐标数值看起来相近就猜 EPSG、中央子午线或分带号。

### 9.2 先确定项目的参考范围

优先顺序是：

1. 供地图层：监管号、合同号等精确一致且无冲突。
2. 首登宗地：单元号一致且无冲突。
3. 报批图层：批复文号一致；明确标记为批次参考范围。
4. 附件矢量：属性业务标识一致且无冲突。

在首个有精确依据的图层中，将命中的图斑按几何并集合成参考范围，允许一个项目多块地。若命中依据全部是未经确认的推断编号，参考范围仍为待确认候选。

没有精确依据时，各图层分别保留最多 5 个无冲突模糊候选，供图上比较；不会直接选择综合分最高的图斑作为事实。

### 9.3 再计算相交关系

对参考范围与报批、首登、附件图斑计算：相交面积、覆盖参考范围的比例、覆盖目标图斑的比例。

普通相交只有面积达到 `max(1平方米, 参考范围面积×0.1%)` 才保留，减少接边碎片。若业务标识直接一致，即使不相交也保留核对记录，并注明“不相交，需核实”。

参考范围覆盖率 = `相交面积 / 参考范围面积`。

目标图斑覆盖率 = `相交面积 / 目标图斑面积`。

空间阶段日志中的强对应要求：恰好一个目标双向覆盖均至少 98%，且整体关系允许采用。只覆盖项目的一部分、只落在大批次内部，不等同于两个对象完全对应。

### 9.4 多图斑、多批次和重复面积

同批复文号、单元号等分组，将与参考范围的交集取并集后统计覆盖率，而不是把面积直接相加。另行输出重复面积，避免重叠图斑把覆盖率抬高。

同一供地、宗地或附件几何被多个项目使用时，建立跨项目争议关系，输出连通的争议项目组，并阻断受影响关系的自动采用。共用报批批次本身不按独占宗地处理。

人工可确认选定范围为共用、独占或排除；共用需要相关项目均有相应共用确认，独占需要唯一确认归属。确认绑定当时的参考范围及所选图斑几何版本。当前不是自动推理项目拆分合并，也不是求解全局最优的一对一分配。

### 9.5 空间证据何时可自动补字段

自动补批复文号/日期，比展示空间候选更严格：

- 参考范围必须来自已经确定的供地图斑。
- 不存在未解决的整体归属阻断，也未被人工排除。
- 若表内声明面积是数值且单位正好为“平方米”，图斑面积与声明面积的差异不得超过 2%。
- 恰好一个批复文号组覆盖供地至少 98%。
- 其他每个文号组的覆盖均小于 1%。
- 人工判为不一致的目标不参与采用。

满足后仅提出批复文号与有效的批复日期补丁，不复制整批面积，不把批次名称写入日期。

这里的面积防护在自动补丁模块仅对表内“平方米”直接生效，不能描述为所有单位都完成同等面积核查；阶段日志还会按换算后的目标面积提示差异。

## 10. 纸质图件怎样参与挂接

人工在原图和地图上提供至少 4 组同名控制点（最多 100 组），拟合仿射变换，检查有限数值、图像范围、共线、退化和残差。默认最大残差容限为 2 米，实际以提交值为准。

通过后输出 PNG、世界文件 PGW、PRJ，按真实坐标叠加，并提取红色闭合区域作为边界候选。候选可进入附件空间匹配，但必须核实印章、图例等误检。

残差小只说明控制点的拟合结果，不能证明原图测绘精度。真实图件的同名点需要人工确认；当前不是无控制点自动配准，也不是对所有拍摄透视和纸张变形进行校正。

## 11. 人工核对怎样影响下一轮

| 人工操作 | 后续作用 |
| --- | --- |
| 采用某字段 | 导出该候选；必要时参与下一轮项目身份和检索 |
| 保留原值 | 该单元格不被候选替换 |
| 确认待定页面属于项目 | 解锁该页候选的采用资格，但仍需要选择具体字段值 |
| 保存历史名称、地址、道路别名 | 更新检索词、正文/台账比较，再重算候选 |
| 指定附件坐标系 | 验证后重新读取/转换几何，再重算空间关系 |
| 确认范围共用、独占、排除、撤销 | 重新核算跨项目争议和自动采用资格 |
| 图形判读“一致” | 在版本有效且无身份冲突时，可帮助确认材料项目归属；不等于自动采用所有字段 |
| 图形判读“不一致” | 排除相应材料项目候选或图斑关系，避免后续自动补丁继续采用 |
| 图形判读“待核实” | 保留待核对结论，不升级为强证据 |

图形判读绑定原件文件摘要、参考范围和所选图斑几何摘要。原件或几何改变后旧判断失效，需要重新核对。不是仅保存一段备注而不参与计算。

## 12. 单元格最终怎样决定写不写

逐单元格汇总：已有值、可自动采用的补丁、成果总表对应值、台账值、文书字段和空间候选。相同值合并来源和方法，不同值保留为不同候选。

| 情况 | 当前处理 |
| --- | --- |
| 原值存在，无不同候选 | 保留原值 |
| 原值存在，出现不同候选 | 标记冲突，默认保留原值 |
| 原值为空，只有一个允许自动采用的值，且归属不待定 | 自动填空 |
| 原值为空，只有一个普通识别/模糊候选 | 展示候选，等待人工采用 |
| 存在多个不同候选值 | 标记冲突，不因来源多或分数高直接选一个 |
| 人工明确采用 | 写入所选值；允许覆盖已有值并保留溯源 |
| 人工明确保留原值 | 保留原值 |
| 没有可靠候选 | 保持空白并记录原因 |

可产生自动资格的主要来源是：明确无冲突的唯一成果总表精确记录、满足限定条件的原始台账代码/单位、严格空间补丁和已有附证据图像的人工核验补丁。文书 OCR 新识别值本身不自动通过。

原始台账使用原始 `XMDM/XMMC` 配对，不把人工补充名称列与另一套原始字段按同一行强行拼接。名称唯一对应一个代码时可提出代码/建设单位补丁；已有项目代码与其冲突时停止。工作台台账自动候选还检查精确对应且原始名称一致。

成果总表也是候选来源，不是独立真值库；上传同一总表时，自身对应值不能被理解成另一来源对其真实性的交叉验证。

导出只写自动采用值和人工已选值，保存单元格、字段、值、原始来源、页面或表格位置、采用方法及选择记录。导出后还执行工作簿保留与结果验证。

## 13. 找不到已有项目时怎样补建

补建结果与已有项目回填分别处理，标记待核实，不默认为正式入库。

- 文书须没有已有明确归属和待确认项目候选，且能识别业务阶段、明确项目名称和文书编号等必要依据。
- 同实体存在多编号、与已有项目业务标识相同或有身份冲突时，进入待消歧。
- 土地供应合同/决定书要求日期在 2018-01-01 至运行当天；其他支持阶段目前没有同样的供应日期门槛。
- 按监管号及合同号/阶段文书编号归集补建文书；同编号字段或身份冲突转待核实，不拼成确定项目。
- 首登图层的有效单元号没有已有项目或相关文书候选、图层中也没有同单元号多条记录时，可形成首登补建候选；否则输出首登补建待消歧。
- 项目类型新标准和目录组织标准尚未提供，相关分类、正式编号和入库口径不擅自推定。

## 14. 异常怎样处理

单张空图片、损坏图片、单页 OCR 失败等逐件记录，正常材料继续；无法读取的原件保留。缓存也需校验，不能因已经有缓存就跳过有效性检查。

例如本次 `image00007.jpg` 实际为 0 字节：记录来源异常并从 OCR 队列剔除，而不是让整批任务因这一张图片失败。识别引擎不可用等整体环境故障仍会让对应环节失败，不能将其伪装成成功。

任务“检索完成，有来源异常待核对”不等于全部原件均已成功识别。失败任务支持原地重试；运行中的任务禁止重复排队。
